# Teaching design

Start with a learner-visible result: for example, a screen retains its counter across recomposition. Introduce a concept, implement one change, then give the learner a check they can perform. Explain distinctions through observable behavior rather than vocabulary alone.

Beginner lessons should explain terminology when first used and separate required knowledge from optional depth. Intermediate lessons should focus on tradeoffs and failure cases. Advanced lessons should document assumptions and boundaries.

Use the template selectively. Supply at least one exercise that changes behavior, one common mistake with a correction, and questions with answers or answer guidance. Keep solutions separate from exercise prompts so the learner can attempt them first.

A roadmap can progress through Kotlin, Android fundamentals, Compose state and layout, architecture, coroutines and Flow, persistence, networking, dependency injection, testing, and a capstone. Change the sequence for the learner's background; this is a suggested course shape, not a requirement for every tutorial.
