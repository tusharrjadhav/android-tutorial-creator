# Repository preparation and publishing

Confirm the destination from the user's instructions and inspect whether it already exists. Preserve its license, conventions, and unrelated files. A new repository should have a clear README, contribution guidance, suitable ignore rules, and a license only when the owner has selected or authorized one; do not silently assign licensing rights.

Prepare the complete local deliverable before handling publishing access. Prefer existing authenticated tooling. Use a private repository when visibility is unspecified and creation is authorized, and disclose that choice. Only publish generated material within the requested scope.

Check authentication without displaying tokens. Never embed credentials in remote URLs or source files. Commit the intended files, push to the correct remote, and verify the remote commit and file listing. Report whether the result is local only, remotely created but unpopulated, or fully published. Do not confuse these states.
